## 레포트 내용
# 1 EOA 의 개념과 특징  
Externally Owned Account 의 약자로서, 흔히 사용하는 지갑의 기술적 명칭이다.  
사용자가 직접 개인키를 제어하는 계정을 뜻한다.  
또한 ETH 네트워크 하 모든 활동은 EOA의 가스비 지불을 통해 시작되며, 스스로 동작하는 스마트 컨트랙트 동작이 불가하다.  

아래와 같은 기술적 한계 및 위험성이 존재한다.  
① 키 관리의 위험성 : 분실 시 복구 불가  
② 낮은 사용자 경험 : 모든 동작 시 가스비 지불 / 일괄 처리 불가  
③ 프로그래밍 불가능 : 지갑으로서의 기능 외 복잡한 조건 포함 불가  

# 2 ERC-4337 기반 지갑  
지갑을 하나의 스마트 컨트랙트로 만드는 기술로서, 개인이 직접 개인키로 서명하지 않아도 프로그램이 스스로 동작할 수 있다.  
사용자가 직접 트랜잭션을 날리지 않아도, 블록체인 네트워크 하에 필요한 작업을 수행하게 된다.  

기존 EOA 방식과 가장 큰 차이점은,  
지갑을 스마트 컨트랙트화하여, 소셜로그인 또는 소셜 복구 등 기능을 추상화하여 편리함을 제공할 수 있다는 것이다.  

# 3 사용성 증가에 따른 운영통제 측면의 새로운 지점  
개인이 직접 하던 복잡한 일을, 시스템이나 제3자가 대신 처리하게 되면서 사용성은 크게 증가하였다.  
이렇듯 작업주체가 개인에서 외부로 이동하며 '신뢰성'과 '책임'에 대한 구조적 논의가 필요하다.  

크게 3가지 정도로 나눌 수 있다.  
① 설계 및 코드 무결성  
스마트 컨트랙트(코드)가 곧 지갑이기에, 해당 코드가 무결한지 끊임없는 입증이 필요하다. 혹여 버그라도 발생할 시에는 모든 사용자에게 영향을 줄 수 있다.  
이렇듯 코드에 대한 보안 및 무결성 감사와 누가 업데이트 권한을 보유할 것인지가 운영의 핵심이 된다.  

② 제3자 프로세스에 대한 신뢰성  
사용자가 직접 가스비를 지불하는 것이 아닌, 제3자가 작업을 처리하는 과정에서 페이마스터 서버 등 대행하는 프로세스가 포함된다.  
이것이 제대로 동작하지 않으면 사용자는 자신의 지갑임에도 트랜잭션을 처리할 수 없으며,  
페이마스터 서버 운영사가 특정 주소에 대해 작업 금지 처리를 하는 등 운영과정에서의 검열 가능성도 발생할 수 있다.  

③ 인증 주체 및 권한 위임  
소셜 로그인 등 기존의 보안 체계에 따라 지갑의 보안 수준이 결정된다.  

# 4 은행의 인증/승인/계정 관리방식과 비슷한점과 다른 점  
인증 매체의 다양화를 통한 로그인 편의성, 분실 시 계정 복구 등이 로직으로 구현되어 있다는 점에서는 유사하나,
ERC-4337의 경우 모든 규칙이 스마트 컨트랙트로 실행되어 운영에 예외 개입이 어렵다는 점에서는 차이가 있다.  

# 5 블록체인 트릴레마란?  
확장성, 보안성, 탈중앙화라는 블록체인 세가지 핵심 가치를 동시에 완벽하게 만족시키기 어렵다는 이론적 한계를 뜻한다.  
특정 성격이 강해지면 다른 쪽이 약화되는 구조로, 최적의 균형점을 찾아야 기술의 대중화와 신뢰성을 이룰 수 있다는 점에서 중요하다.  

# 6 L2(레이어2)의 등장  
기존 블록체인 (Layer 1) 외 추가적인 층을 두어, '복잡한 연산은 밖에서 처리'하고 결과만 Layer 1에 저장한다는 개념을 표방한다.  
트릴레마 관점에서 보았을 때에, L1은 보안성과 탈중앙화를 강화하여 유지하되, 대량의 트랜잭션은 Layer 2에서 담당하여 부족할 수 있는  
확장성을 끌어올렸다는 점에서 최적의 균형점을 찾았다고 볼 수 있다.  
마치 대량 트랜잭션 처리를 위한 별동대를 구성한 것과 같은 개념이다.  

# 7 마무리  
개인이 직접 서명하고 트랜잭션을 올리는 방식을 벗어나 편의성이 증가하였고,  
스마트 컨트랙트 체계에서 동작하며 높은 수준의 추상화와 개입 불가능한 탈중앙화 성격도 크게 강화되었다.  
L2 레이어의 도입으로 트릴레마까지 어느정도 보완한 상황까지 블록체인은 발전하였다.  

하지만 기술의 발전이 되었다고하여, 대중의 신뢰성도 비례하여 증가하지는 않는다고 생각한다.  
기존 금융이 크게 발전할 수 있었던 이유는 크게 2가지라고 생각하는데 편의성과 안정성이다.  
쉽게 내 자산을 예탁할 수 있으며, 잘못되더라도 어느정도 중앙기관으로부터 보장받을 수 있기 때문이다.

따라서 아래와 같은 방향으로 나아가는 것이 좋다고 생각한다.  
장부와 같은 것은 기술적으로 조작이 불가능한 블록체인 내 구성하여 안정성을 확보하되,  
ERC-4337과 같은 추상화를 도입하여 기존 은행 앱과 같은 편의성을 제공한다.  
마지막으로는 사고 발생 시 금융회사가 복구 권한을 행사하여 자산을 보호할 수 있는 책임구조를 마련하여  

최종적으로는 기술적 신뢰는 블록체인을 통해 강화하고, 운영적 책임은 금융사에서 보증하는 구조로 나아가는 것이 좋다고 생각한다.
